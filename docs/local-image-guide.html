Mac 本機 ComfyUI 生圖入門（給影片流程用的素材）

你的機器：MacBook Pro M5 Pro、18 核 CPU / 20 核 GPU、64 GB 統一記憶體、剩 505 GB 空間，尚未裝 ComfyUI。這份教學說明本機能做什麼、用哪些模型、一張圖要等多久，以及哪些圖做出來能直接接回 MiniMax H3 影片流程。資料日期 2026-09-17。

1. 本機能做什麼、不能做什麼

✔ 適合本機

  • 生圖：角色設計、參考圖集、場景關鍵幀、首尾幀——不限次數、$0
  • 圖片編輯：換角度/表情/服裝、保持同一人（Qwen-Image-Edit）
  • 合成參考圖（文章那種左景右人拼圖）、去背、放大
  • 寫 prompt、整理分鏡表、試 seed

64 GB 統一記憶體＝任何 20B 級生圖模型都塞得下，不會 OOM，只是比 5090 慢 10–30 倍。

✘ 不要在本機做

  • MiniMax H3 影片生成：MPS 上 33B 影片模型一段 15 秒要 1–3 小時，而且很多 CUDA kernel 沒有 Mac 版。這是 RunPod 5090 的工作。
  • LoRA 訓練：Mac 上要 3–8 小時；RunPod 5090 上 30–60 分鐘、$1。
  • 批量放大到 4K 影片：慢且沒有 NVENC。
分工原則：「想」在 Mac，「算」在雲端。本機把所有靜態素材做到滿意，雲端只負責把圖變影片——這樣 RunPod 的每一小時都在產出成品，不是在試錯。

2. 安裝（15 分鐘）

✔ 2026-09-18 已用方案 B 裝好在 ~/ComfyUI（自包含，rm -rf ~/ComfyUI 即移除）。啟動：/Applications/ComfyUI.app（獨立視窗，關掉就停伺服器；瀏覽器也能開 127.0.0.1:8188）。說明、App 選單、四週學習計畫：ComfyUI-Mac/README.md；測速：ComfyUI-Mac/scripts/bench.py。

方案 A：ComfyUI Desktop（推薦新手）

  1. 到 comfy.org/download 下載 macOS（Apple Silicon）版 dmg，拖進 Applications。
  2. 第一次開啟會問安裝位置，選一個大硬碟目錄，例如 ~/ComfyUI（模型會放在 ~/ComfyUI/models/）。它會自己裝 Python 與 PyTorch（MPS 版），不用碰終端機。
  3. 開啟後左側 Template Library 有官方 workflow，點一個會提示缺哪些模型並可一鍵下載。

方案 B：終端機安裝（想自己控制版本）

brew install uv
git clone https://github.com/comfyanonymous/ComfyUI ~/ComfyUI && cd ~/ComfyUI
uv venv --python 3.12 .venv && source .venv/bin/activate   # 你系統的 Python 3.14 太新，用 3.12
uv pip install torch torchvision torchaudio                # macOS 自帶 MPS 支援
uv pip install -r requirements.txt
python main.py --listen 127.0.0.1                          # 開 http://127.0.0.1:8188

之後裝 ComfyUI-Manager（Desktop 版內建）方便找缺的節點：git clone https://github.com/Comfy-Org/ComfyUI-Manager custom_nodes/ComfyUI-Manager。

方案 C：Draw Things（App Store，最無腦）

原生 Metal 實作，同一台 Mac 比 ComfyUI 快 20–40%，模型內建下載。缺點是 workflow 不能帶去 RunPod 重用、進階節點少。適合先玩兩天感受一下再進 ComfyUI。

2026-09 這個時間點，開源生圖有三個主流家族，都在 ComfyUI 原生支援：

🎯 精緻方案（你的首選）

角色主圖FLUX.1 Krea dev，1024×1024 或 1344×768，28 步，CFG 3.5 參考圖集Qwen-Image-Edit-2511（多圖輸入：主圖 + 指令「同一人、轉 3/4 側面、換白襯衫」） 場景關鍵幀Qwen-Image 1344×768，20 步（構圖與指令遵從最準） 放大4x-UltraSharp（ESRGAN）到 2K 再縮回，細節更扎實 每張成本時間：2–5 分鐘/張，見 §4

一晚 3 小時約能產 40–60 張定稿級素材，夠一個角色 + 10 個場景。

⚖️ 平衡方案（先摸索用）

草稿 / 找構圖Z-Image-Turbo 8 步，1024²，30–60 秒一張，一晚可抽 200 張 定稿挑中的構圖用 Flux Krea 以 img2img（denoise 0.5）重繪一次 一致性Qwen-Image-Edit-2511（同上） 每張成本草稿 <1 分鐘、定稿 3 分鐘

新手前兩週建議這條：多抽、多看、快速學 prompt，再切精緻方案。

授權提醒：FLUX.1-dev / Krea dev 是非商用授權；要商用的素材改用 Qwen-Image 或 Z-Image（Apache-2.0）。H3 影片本身也有授權限制（見主教學 §2）。

4. 每張圖要多久（M5 Pro 20 核 GPU、64 GB 預估）

✔ 標記為你這台機器的實測；其餘由 M3 Max / M4 Pro 換算（Z-Image 實測比推估快約 1.5×，其他列可能也偏保守）。原推估說明：Apple Silicon 沒有公開的 M5 Pro ComfyUI 數據，以下由 M3 Max / M4 Pro / M1 Max 實測換算（M5 GPU 有 Neural Accelerator 與原生 FP8/BF16，估計比 M4 Pro 快 1.3–1.8×）。請把它當「數量級」，安裝後用 §5 的第一張圖實測校正。

對照：同樣的圖在 RunPod 5090 上 Z-Image 2–3 秒、Flux 10 秒、Qwen-Image 20 秒。所以「要抽 500 張找靈感」也可以開 5090 一小時 $1 做完；本機的價值是零成本、隨時可用、不用上傳下載。

MPS 地雷（實測踩到）：檔名帶 fp8_scaled / fp8mixed 的模型在 Mac 會報 Undefined type Float8_e4m3fn——Metal 沒有 fp8 dtype，ComfyUI 的 scaled-fp8 反量化路徑無法執行。一般 fp8_e4m3fn（如 Qwen-Image）可以，會自動升成 bf16。替代：GGUF Q8（裝 ComfyUI-GGUF）、int8_convrot、或 bf16。文字編碼器的 t5xxl_fp8_e4m3fn_scaled / qwen_2.5_vl_7b_fp8_scaled 沒問題。
加速三招（M 系列）：① 第一次跑會慢 2–3 倍（編譯 Metal kernel），看第二張才準。② 若模型是 fp8 檔而 Mac 跑不動，換 GGUF Q8 或 bf16 版。③ 舊版 ComfyUI 在 M1–M3 要加 --fp16-unet --fp16-vae；M5 原生支援 BF16 通常不需要，若某模型異常慢再試。

5. 第一張圖：實際操作（Z-Image-Turbo，10 分鐘）

  1. ComfyUI → Template Library → Image → Z-Image Turbo（沒有的話更新 ComfyUI）。
  2. 點 template 會列出缺的三個檔並可下載：z_image_turbo_bf16.safetensors（diffusion_models）、qwen_3_4b.safetensors（text_encoders）、ae.safetensors（vae）。
  3. Prompt 貼你的角色聖經（主教學 §8.3 Step 1）；解析度 1344×768（跟 H3 影片畫布一致，省得之後裁）；steps 8、cfg 1.0；seed 設 fixed。
  4. Queue。第一張慢屬正常；記下第二張的秒數，回頭把 §4 的表校正成你的真實數字。
  5. 喜歡的圖：seed 記進檔名（§7），這就是你角色的「出生證明」。

接著換 Flux Krea template 用同一段 prompt 再生一張，比較質感差異——兩個模型的「臉」會不一樣，選一個當你角色的家，之後不要換。

6. 哪些素材值得在本機做（如何接回影片）

H3 影片流程需要的所有靜態輸入都能在本機先做好。按投資報酬率排序：

素材值得？怎麼用進影片本機做法
角色主參考圖（正面半身、乾淨背景）必做R2V 參考圖 #1；所有 Edit 的來源Flux Krea，抽到滿意記 seed
角色參考圖集（3/4 側、側面、全身、5 表情、3 光線、每套服裝）必做R2V 參考圖 #2 依場景挑；也是之後訓 LoRA 的資料集Qwen-Image-Edit-2511 多圖輸入，指令「same person, turn 45°…」
場景關鍵幀（每個場景一張首幀，含角色）必做I2V 的 first_frame；每 5–8 段接龍後重新錨定Qwen-Image 生空場景 → Edit 把角色放進去（或直接生）
首尾幀對（動作起點 / 終點）值得FL2V：給 first + last，H3 補中間，動作可控度大增Edit：以首幀為基礎改姿勢/位置
合成參考圖（左景右人，文章那招）值得I2V 單張同時鎖場景與人ComfyUI Image Concatenate 節點或 Preview → 任何修圖軟體拼
服裝/道具設定圖有幫助寫進 prompt 的依據；R2V 可當第二張參考Edit：「same outfit on mannequin, front and back」
場景空景（無人）有幫助換角色/多角色時當底圖；桌面桌布Qwen-Image 1344×768
字幕/UI 版型圖有幫助文章要 H3 生字幕 UI 很吃運氣；改成後製疊字更穩本機做透明 PNG 版型，ffmpeg/剪輯軟體疊
放大後的 4K 靜態圖小幫助H3 輸入是 768p，放大沒必要；只有做海報/縮圖用4x-UltraSharp
大量風格探索圖不值得在本機—要抽幾百張時開 5090 一小時比較划算
送上雲端前的檢查：解析度 1344×768（16:9）或 768×1344（9:16）、PNG、同一角色的所有圖放同一資料夾、檔名含 seed。上傳只要一次（拖進 RunPod 的 FileBrowser 8080 或 ComfyUI LoadImage），之後每次 Pod 開機都在 network volume 上。

8. 常見問題

出圖比表上慢 3 倍第一張在編譯；或模型是 fp8 且 ComfyUI 版本沒對 MPS 做 fp8 → 換 bf16/GGUF；或活動監視器看記憶體壓力是否變黃（同時開太多 app）。 黑圖 / 全灰VAE 精度問題，加 --fp16-vae 或換 ae.safetensors 官方版。 "MPS backend out of memory"降解析度或加 PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0 環境變數；64 GB 通常不會遇到。 Template Library 沒有某模型更新 ComfyUI（Desktop：設定 → 更新；終端機：git pull && uv pip install -r requirements.txt）。 模型下載很慢HuggingFace 直連通常 20–50 MB/s；40 GB 的 Qwen-Image 約 20 分鐘，先下 Z-Image（12 GB）玩。 想更快Draw Things（Metal 原生）或 mflux（MLX）跑 Flux/Qwen 快 20–40%，但 workflow 不通用；素材做完再回 ComfyUI 也行。
